# 第五次作业：并发传感器数据处理与时间同步

## 程序介绍

`sensor_sync` 是一个基于 C++ 多线程的传感器数据时间同步程序，模拟 RoboMaster 视觉系统中相机与 IMU 数据的时间戳匹配过程。

### 功能特性
- 两个生产者线程（相机 + IMU）并发读取数据文件
- 有界线程安全队列作为数据缓冲（互斥锁 + 条件变量实现）
- 一个消费者线程从队列取数据，按传感器类型分类保存
- 基于二分查找的时间戳匹配算法，为每个相机帧找到时间最接近的 IMU 数据
- 支持异常处理与线程安全退出

### 编译运行
```bash
mkdir build && cd build
cmake ..
make
./sensor_sync ../data/camera.txt ../data/imu.txt result.txt
```

### 数据格式
- **相机数据**：每行两个整数 `序号 时间戳(微秒)`
- **IMU 数据**：每行两个整数 `序号 时间戳(微秒)`

### 输出格式
```
CAMERA <camera_sequence> IMU <imu_sequence> DELTA <absolute_delta_us>
CAMERA <camera_sequence> UNMATCHED
```

## 问题回答

### 1. 队列已满或为空时，线程如何进入等待状态？

使用 `std::condition_variable` 的 `wait()` 方法让线程进入阻塞等待状态。

- **生产者线程**：调用 `cond_full_.wait(lock, predicate)`，当队列满（`size() >= max_size_`）时阻塞，释放互斥锁并挂起线程。消费者取走数据后调用 `cond_full_.notify_one()` 唤醒一个生产者。
- **消费者线程**：调用 `cond_empty_.wait(lock, predicate)`，当队列为空且队列未关闭时阻塞。生产者放入数据后调用 `cond_empty_.notify_one()` 唤醒消费者。

`wait()` 的第二个参数是 lambda 谓词，用于防止虚假唤醒（spurious wakeup）——线程被唤醒后会重新检查条件，如果不满足则继续等待。

### 2. 如何判断最后一个生产者已经结束？

使用 `std::atomic<int>` 原子变量 `g_producers_finished` 来计数已完成的生产者数量。

每个生产者线程结束时，调用 `g_producers_finished.fetch_add(1)` 原子地将计数器加 1，并获取加之前的旧值。如果 `旧值 + 1 >= 总生产者数(TOTAL_PRODUCERS)`，则说明自己是最后一个结束的生产者，此时调用 `g_queue.close()` 关闭队列。

用原子变量而不是普通 int + mutex，是因为原子操作在硬件层面保证了原子性，不需要加锁，性能更好且更简洁。

### 3. 为什么关闭队列后仍然需要允许消费者读取剩余数据？

关闭队列（`close()`）只是**禁止继续入队**，但队列中可能还有生产者已经放入但消费者尚未处理的数据。如果关闭后消费者直接退出，这些数据就丢失了。

正确的退出逻辑是：
1. 所有生产者结束 → 关闭队列（不再接受新数据）
2. 消费者继续从队列取数据，直到**队列为空且队列已关闭**时才退出
3. `wait_and_pop()` 在队列为空且关闭时返回 `false`，消费者据此判断所有数据已处理完毕

这样保证了"不丢数据"——所有生产者放入队列的数据最终都会被消费者处理完。

### 4. 时间戳匹配算法的具体流程和复杂度是什么？

**算法流程**：
1. 消费者先收集所有相机和 IMU 数据
2. 按时间戳对 IMU 数据排序（升序）
3. 对每个相机帧的时间戳，用**二分查找**在 IMU 数组中找到第一个时间戳 ≥ 相机时间戳的位置
4. 比较该位置和前一个位置（即 `>=` 和 `<` 相机时间戳的两个相邻 IMU），取时间差绝对值更小的那个
5. 输出匹配结果

**时间复杂度**：
- 排序 IMU 数据：O(n log n)，n 为 IMU 数据条数
- 对每个相机帧做二分查找：O(m log n)，m 为相机数据条数
- 总复杂度：O(n log n + m log n) = O((m + n) log n)

**空间复杂度**：O(m + n)，需要存储所有相机和 IMU 数据。

相比线性遍历的 O(m × n)，二分查找在数据量大时效率高很多。

### 5. 如何处理时间差相同、时间戳相同等边界情况？

- **时间差完全相同**（一个在前一个在后，差值相等）：选择序号更小（时间更早）的那个 IMU 数据，保证结果的确定性和可复现性。
- **时间戳完全相同**（IMU 时间戳 = 相机时间戳）：二分查找会直接定位到该位置，时间差为 0，是最优匹配。
- **相机时间戳早于所有 IMU**：二分查找返回第一个 IMU（result_idx = 0），前一个位置不存在，直接取第一个。
- **相机时间戳晚于所有 IMU**：二分查找返回 -1（所有 IMU 都小于相机时间戳），此时取最后一个 IMU（result_idx - 1 = n-1）。
- **没有任何 IMU 数据**：返回 UNMATCHED。

### 6. 如果某个生产者读取文件失败，如何保证其他线程能够正常退出？

当某个生产者打开文件失败时：
1. 该生产者立即将 `g_producers_finished` 原子计数加 1
2. 直接调用 `g_queue.close()` 关闭队列
3. 消费者被唤醒后，发现队列为空且已关闭，正常退出

为什么失败的生产者直接关闭队列而不等待另一个？因为一旦有一个生产者失败，数据就不完整了，继续等待另一个生产者完成没有意义——直接关闭队列让所有线程尽快退出，避免死等。

同时，`push()` 操作在队列关闭时会抛出异常，生产者捕获异常后也会安全退出，不会卡死。

另一个正常运行的生产者在尝试 `push()` 时如果发现队列已关闭，也会捕获异常并提前结束，不会阻塞。
