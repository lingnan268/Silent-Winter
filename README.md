Q：小陀螺为什么给传统自瞄算法带来巨大挑战？
A：小陀螺作一个作高速旋转的物体，在他旋转的同时所装配的装甲板也会随着他进行高速的旋转，而在自瞄算法的基本原理上，它是由相机拍摄到画面，到检测到敌方装甲板，再到算出装甲板的位置，根据当前位置检测下一位置，最后告诉云台向哪里转，最后发射子弹，是有一定的过程的，而这所有的过程都是需要时间的。传统的算法更倾向于假设目标做的是相对平稳的运动，而没有太剧烈的动感所产生的一切特性。所以传统的算法不适合面对小陀螺这种高速旋转，并且给视觉算法带来诸多负面影响的运动。在小陀螺的机制中机器人原地高速旋转，这个时带来的第一个负面影响，就是高速旋转的同时拍摄到的装甲板，还有上传的影像会变得模糊，传感器上的像会拖成一片，而装甲板上的灯带本来是清晰的亮线条，在这里就会被拖成一条模糊的光带，或者变成模糊的弧线，甚至变得难以检测，这种模糊会一直传下去，从画面模糊到装甲板检测不准，再到角点的位置偏移，最后预测出错很难打中。第二点，装甲板不是直线运动，而是圆周运动，也就代表在机器人旋转的时候，每块装甲板都在做圆周运动，不能够用直线模型去预测圆周轨迹。第三点，在做圆周运动的同时，装甲板会不断的出现和消失，这个时候检测到的画面，就是模糊的灯条一会儿出现一会儿消失，很难稳定的持续跟踪。第四点，id跳变的问题，跟踪算法给每块装甲板分配一个id持续跟踪，但是在装甲板高速旋转的同时，一块板刚转出视野另一块板又迅速转进来，算法很容易搞混最终导致重新分配id，id出错就无法实现稳定的追踪检测打击，因为算法很可能把两块不同装甲板的位置变化，当成了同一块的运动轨迹。第五可打击的时间很短只有在装甲板正对着的时候或者说稍微有些偏离的时候才能被打中机器人高速旋转的时候每块装甲板能够打击的时间很短，这还要考虑到画面的上传，云台的转动，以及弹丸发射所需要的时间，这里面的时间很难去精确地估算，如果在装甲板正对着发射弹丸的机器人的时候，机器人才会做出发射弹丸的决策，那么很可能这一块装甲板已经转走，而原本要打击的位置正处于两个装甲板之间，很难凭借运气击中
